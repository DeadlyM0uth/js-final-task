Итоговая практическая работа к 24.10.2026. Одно веб-приложение: Express-сервер с REST API и простой интерфейс на чистом HTML/JavaScript. Все дела хранятся в MongoDB, поэтому после перезапуска данные остаются на месте.

## Устройство приложения

Сервер состоит из пяти небольших модулей, каждый решает одну задачу: `config.js` читает и проверяет переменные окружения, `store.js` отвечает за подключение к MongoDB и перевод документов в формат API, `validation.js` проверяет `title`, `runId` и `done`, `app.js` описывает маршруты и обработку ошибок, `server.js` поднимает процесс и корректно завершается по сигналу. Интерфейс лежит в `public/` и обращается к тем же маршрутам, что и проверяющий: отдельного «внутреннего» API нет.

```
src/          config.js store.js validation.js app.js server.js
public/       index.html app.js styles.css
scripts/      init-db.js smoke-test.js generate-token.js
Dockerfile docker-compose.yml Caddyfile  docs/DEPLOY.md
```

Фреймворков на фронтенде нет: форма входа по токену, поле `runId`, добавление дела, отметка выполнения, переименование и удаление. Токен в исходники не встроен — пользователь вводит его сам, он хранится в `sessionStorage` вкладки.

## Данные

Коллекция `tasks` в базе `todo_students`. Внутренний `_id` (ObjectId) в ответы API не попадает.

| Поле API | Тип | Поле в MongoDB | Кто задаёт |
|---|---|---|---|
| `id` | строка UUID | `id` (string, уникальный индекс) | сервер |
| `ownerLogin` | строка | `ownerLogin` | сервер из `OWNER_LOGIN` |
| `title` | строка 1–200 после trim | `title` | клиент, сервер проверяет |
| `done` | boolean | `done` | сервер (`false` при создании), далее `PATCH` |
| `runId` | строка `A-Za-z0-9_-` 1–64 | `runId` | клиент |
| `createdAt` | строка ISO 8601 UTC | `createdAt` (BSON Date) | сервер |

Маршруты повторяют ТЗ, все оканчиваются на «/», все `/api/` защищены `Authorization: Bearer <токен>` и отвечают `application/json`:

| Запрос | Успех | Ошибки |
|---|---|---|
| `GET /login/` | 200, `text/plain`, логин | — |
| `GET /api/author/` | 200, `{login, fullName}` | 401 |
| `POST /api/tasks/` | 201, созданное дело | 400, 401, 503 |
| `GET /api/tasks/?runId=…` | 200, массив (может быть `[]`) | 400, 401, 503 |
| `GET /api/tasks/:id/` | 200, дело | 400, 401, 404, 503 |
| `PATCH /api/tasks/:id/` | 200, обновлённое дело | 400, 401, 404, 503 |
| `DELETE /api/tasks/:id/` | 204 без тела | 400, 401, 404, 503 |

Отдельно создано персональное дело «Итоговая работа 24.10.2026: vadim_smirnov_4150» с `runId="manual"`; его создаёт скрипт инициализации с фиксированным UUID, поэтому повторный запуск дубля не даёт.

## Где размещать БД

| Вариант | СУБД | Тариф | Ограничения | Проверка 30.10.2026 | Источник |
|---|---|---|---|---|---|
| Собственный VPS (выбран) | MongoDB 7.0 | нет отдельной оплаты, входит в VPS | диск VPS, доступ только с localhost и через SSH-туннель | проверено, БД поднята в Docker | — |
| Timeweb Cloud | MongoDB | платно, «Облачный MongoDB от 790 ₽»; постоянного бесплатного тарифа не заявлено | объём, бэкапы и allowlist на странице не видны (контент рендерится скриптами) | страница доступна, детали не подтверждены | https://timeweb.cloud/services/mongodb |
| MongoDB Atlas | MongoDB | бесплатный M0 (512 МБ, без карты), платные M10+ | только allowlist IP, лимит соединений, регион | официальная страница отдала HTTP 403 из сети выполнения — подтвердить вручную | https://www.mongodb.com/pricing/ |
| Supabase | PostgreSQL (MongoDB не поддерживается) | Free $0 постоянно: 500 МБ БД, 2 проекта, пауза после недели простоя | только Postgres — переписывать код ради чужой СУБД нет смысла | проверено | https://supabase.com/pricing |
| Факультетский Helios | — | — | нужен доступ от университета | доступ пока не получен, раздел заполняется после выдачи | — |

Выбран свой VPS, потому что MongoDB 7.0, база и приложение живут на одной машине: нет внешних лимитов и allowlist, проверяющему не нужен аккаунт в облаке, а ограниченного пользователя Mongo можно выдать точечно. Supabase отпадает из-за PostgreSQL, Timeweb Cloud и Atlas требуют регистрации и оплаты либо внешнего allowlist.

## Запуск

```bash
cp .env.example .env          # заполнить токен, пароли, домен
docker compose up -d --build  # mongo + app + caddy
docker compose run --rm db-init
curl -s https://todo.smirnov-vadim.ru/login/
```

Локально без Docker: `npm ci`, `npm run init:db`, `npm start`. Проверка контракта на запущенном приложении — `npm run test:smoke` (54 проверки), новый токен — `npm run token:gen`.

Версии: Node.js 22 LTS (образ `node:22-alpine`), MongoDB 7.0 (образ `mongo:7.0`), драйвер `mongodb` 7.8, Express 5.3.

Структура коллекции и её инициализация описаны в [docs/SCHEMA.md](docs/SCHEMA.md), развёртывание, сертификат и доступ проверяющего — в [docs/DEPLOY.md](docs/DEPLOY.md). Токены и пароли хранятся только в `.env` и в репозиторий не попадают.
